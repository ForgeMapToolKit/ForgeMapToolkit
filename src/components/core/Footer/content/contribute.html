How to Contribute

This guide is for people who want to work on ForgeMapToolkit itself, not for reporting bugs or requesting features. If you ran into a problem while using FMT or have an idea for a new tool, the Report an Issue guide is the better place to start.

Getting Set Up

FMT is built as an Electron application with React and Vite. To work on it locally you fork the repository, clone your fork, and install dependencies with npm. From there the usual Vite and Electron dev scripts get you a running instance with hot reload.

Fork and clone github.com/ForgeMapToolKit/ForgeMapToolkit, then run npm install. Use npm run electron:dev to start the Vite dev server and Electron together with hot reload. Running npm run dev alone only starts the Vite server without the Electron shell.

Design System First

FMT follows a strict design system called TRACE. Before touching any UI code, read through TAB_DESIGN_LAW.md and UI_PHILOSOPHY.md, and get familiar with tokens.css. No hardcoded colors, spacing, or typography values. Everything goes through tokens, and the Wreckage tab is the reference implementation if you want to see the system applied in practice.

Pull requests that introduce hardcoded values or break the established BEM-like class conventions will get sent back for changes, so it is worth reading these documents fully before starting on anything visual.

Where to Start

FMT has been developed mostly by a single person so far, and there is no curated list of good first issues yet. If you want to contribute, the most reliable way to find something worth working on is to reach out directly and ask what currently needs attention.

Submitting Changes

There is no formal pull request workflow in place yet, since the project has not had outside contributors up to this point. Open a pull request with what you have, and expect the process around reviewing and merging contributions to take shape as more people get involved.
